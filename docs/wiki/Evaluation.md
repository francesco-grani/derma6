# Evaluation

Derma6 uses [deepeval](https://github.com/confident-ai/deepeval) to measure the quality of all six agent tools and the agentic RAG pipeline. Results are visible in the Admin → Eval Dashboard.

---

## Quick start

```bash
# 1. Refresh actual_output from live tool runs (do this before every eval run)
uv run python eval/capture_outputs.py --update-golden

# 2a. Run via pytest (CI-friendly, exit code reflects pass/fail)
uv run pytest --run-eval eval/test_deepeval_evaluations.py -v

# 2b. Or trigger from the Admin UI: Admin → Eval Dashboard → Run Eval Suite
```

---

## Architecture

```
eval/
├── golden_dataset.json          # 24 test cases — inputs, expected outputs, retrieval context
├── capture_outputs.py           # calls tools directly, writes fresh actual_output to the dataset
├── run_eval_json.py             # standalone runner — stdout: JSON array of results
└── test_deepeval_evaluations.py # pytest wrapper of the same 28 test configurations
```

### The golden dataset

Each entry in `golden_dataset.json` has:

| Field | Purpose |
|---|---|
| `id` | Stable identifier (e.g. `spf-01`, `kb-03`) |
| `tool` | Which tool produces the output |
| `input` | Exact string passed to the tool |
| `actual_output` | What the tool currently produces — **refreshed by `capture_outputs.py`** |
| `expected_output` | Human-written description of desired behaviour — used by contextual metrics |
| `retrieval_context` | Chunks returned by the RAG pipeline — populated for KB cases by the capture script |
| `tags` | Freeform labels for filtering |

`actual_output` is not handwritten. It is always generated by calling the real tool. If you edit `actual_output` by hand you will create a gap between what you test and what the tool produces.

### The capture script

`capture_outputs.py` calls each tool directly (no HTTP), patches the profile store with an in-memory SQLite, and for KB cases runs the full agentic RAG pipeline and extracts `reranked_docs` as `retrieval_context`. Run it before any eval that includes KB cases, or after any change to tool logic.

```bash
# Refresh everything
uv run python eval/capture_outputs.py --update-golden

# Refresh specific cases only
uv run python eval/capture_outputs.py --ids kb-01,kb-02,kb-03,kb-04 --update-golden
```

## Evaluator types

### GEval — LLM-as-judge

Used for 20 of the 28 tests. Sends `(input, actual_output)` to `gpt-4o-mini` with criteria written in plain English; returns a score (0–1) and a reason string. Good for subjective quality — SPF enforcement, conflict verdict format, skin type classification, phased scheduling correctness.

```python
GEval(
    name="SPF Standard Enforcement",
    criteria=(
        "The response must recommend SPF 50+ as the minimum. "
        "It must NOT suggest SPF 30 or SPF 15 is sufficient."
    ),
    evaluation_params=[SingleTurnParams.INPUT, SingleTurnParams.ACTUAL_OUTPUT],
    threshold=0.7,
    model="gpt-4o-mini",
)
```

### Programmatic — pure Python

Used for the 4 routine sequencer tests. No LLM call — deterministic, fast, and immune to judge hallucination. `gpt-4o-mini` consistently scored correct routine outputs ~0.3 because it believed `serum → moisturiser` was wrong. Replaced with two classes:

- **`_RoutineOrderMetric`** — verifies `cleanser:`, `serum:`, `moisturiser:`, `spf:` appear in ascending string-position order
- **`_UnclassifiableItemsMetric`** — verifies every input item appears in either the routine list or the `Unclassifiable items:` section

### Contextual RAG metrics

Used for the 8 KB RAG pipeline tests (the 4 KB cases evaluated twice — once for answer quality, once for retrieval quality). Requires `retrieval_context` to be populated by `capture_outputs.py`.

| Metric | Question it answers |
|---|---|
| `ContextualRelevancyMetric` | Are the retrieved chunks on-topic for the query? |
| `ContextualPrecisionMetric` | Are the most useful chunks ranked highest? |
| `ContextualRecallMetric` | Did retrieval capture enough to answer the question? |

## Test categories and coverage

28 test configurations across 7 categories:

| Category | Cases | Evaluator types |
|---|---|---|
| SPF Recommender | 4 | GEval, AnswerRelevancy |
| Conflict Checker | 4 | GEval |
| Routine Sequencer | 4 | Programmatic |
| Skin Type Advisor | 4 | GEval |
| Introduction Scheduler | 4 | GEval |
| KB — Answer Quality | 4 | AnswerRelevancy, Faithfulness, GEval |
| KB — RAG Pipeline | 8 | ContextualRelevancy, ContextualPrecision, ContextualRecall |

The Admin dashboard filter pills let you view one category at a time. Score chips are colour-coded green (pass) / red (fail) and show `[kind] metric-name: score / threshold` on hover.

## Known failing tests

Two tests are intentionally failing — they surface real tool bugs, not eval bugs:

**`routine-02` — Unclassifiable Items Reporting**
The routine sequencer's retriever fallback has a second loop that returns the first step found in KB content regardless of whether the ingredient matches. Unknown items like `mystery_serum_xyz` get classified as `cleanser`. Fix: remove the second loop in `_classify_ingredient` ([routine_sequencer.py](../../backend/tools/routine_sequencer.py)).

**`intro-02` — Conflict Warning in Schedule**
The introduction scheduler only warns about `do-not-use` pairs. The conflict table has no `do-not-use` entries — all pairs are `use-at-different-times`. So no warnings are ever produced. Fix: either add `do-not-use` entries to the conflict table, or also warn for `use-at-different-times` pairs in the scheduler.

## Adding new test cases

1. Add an entry to `eval/golden_dataset.json` with `actual_output: ""` (placeholder)
2. Run `capture_outputs.py --ids <new-id> --update-golden` to populate `actual_output`
3. Add a test function to `eval/test_deepeval_evaluations.py`
4. Add the matching config to `_TESTS` in `eval/run_eval_json.py` (include `category`)

The `capture_outputs.py` tool map lives in `_TOOL_CALLERS`. If you add a new tool, register it there.

## Running in CI

```bash
uv run pytest --run-eval eval/test_deepeval_evaluations.py -v --tb=short
```

The `--run-eval` marker is required; without it pytest skips all eval tests. Exit code is non-zero if any test fails — suitable for a CI gate.

The judge model (`gpt-4o-mini` via OpenRouter) requires `OPENROUTER_API_KEY`. Programmatic tests run without any API key.
